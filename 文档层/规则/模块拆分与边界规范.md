# 模块拆分与边界规范

## 契约优先

模块的对外身份是它的输入、输出与失败行为约定；实现方式、文件结构和迭代过程不进入约定。满足约定即可替换实现，调用方只依赖约定。

约定写在模块主记录，不复制到代码注释。实现可独立替换；调用方使用公开约定，不读私有实现。

## 何时拆分

按职责是否独立演进判断，不按函数数量、代码行数或并行 Agent 数量判断。

- 同一职责、一个实现、一个调用方：留在一个模块。
- 拆分只发生在多个角色确实各自独立变化时。
- 不预拆：不为“将来可能需要”预留抽象层、插件系统或空目录；出现第二个实现或第二个调用方再拆。
- 模块移动不改身份；拆出独立职责才新建模块身份。

## 契约三角色

一个可替换的能力由三面组成，用它们判断边界：

- 契约面：定义输入、输出、词汇和失败语义，是模块的公开约定。
- 实现面：提供具体实现，可被替换，不改变契约面。
- 调用面：谁使用、通过什么约定使用；调用面不反向决定契约面。

三面可以同在一个模块，也可以分属不同模块；只有它们独立演进时才拆。一个面单独存在不构成拆分理由。

## 命名角色

命名描述当前真实职责，不命名首个实现、未来扩展或框架基类。职责变化时改名，不为兼容保留误导性旧名。命名确切对象，不用隐喻词。

## 要求证据

不为没有真实调用方的参数、选项、抽象或兼容路径预留位置。可配置性不等于需要默认值；没有当前调用方证据的公开选择，要么由使用方明确取值，要么推迟到有证据时再定。

## AI 步骤契约

模块内不接入模型 API 调用层。需要 AI 执行的步骤按显式输入输出端口约定：

- 模块准备交给宿主 Agent 的上下文，声明期望的结构化返回。
- 执行权归宿主 Agent 的既有 AI 能力，模块不持有模型调用。
- 交给模型的内容只含任务相关概念，不带实现、界面或传输细节。
- 该步骤的输入上下文与返回结果必须留痕、可重建；模型可见的内容必须能从记录还原。

模块只负责“备好上下文、接收结构化结果、继续下一步”，仍是可复用组件。

## 质检与激活点

质检按需，不强制。需要时由 AI coding 在设计阶段给出质检项与激活点：谁、在什么时候运行它，并与对应模块或步骤绑定。不预置通用脚本，也不要求每个模块都有质检。

有激活点的质检才算生效；只写在文档里、没有运行时机的检查不产生约束力。
