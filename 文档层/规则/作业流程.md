# 从开始到接续的作业流程

## 新项目与首次开发

1. 读取 doc://demo/cli-reference，复制骨架到新目录并绑定文档、代码和治理数据位置。把 project://demo 替换为新项目的身份由 init 完成。
2. 用真实意图填写项目主记录，决定需要几个模块。复制模块主记录模板，每个模块先用 planned。代码资产在 assets.json 登记 URI、相对位置及 implements；不要复制示例模块的 URI。
3. 在主记录约定输入输出和依赖；能独立开发的模块分配互不重叠的写入范围。未确定的公开约定先讨论清楚，普通实现选择由 Agent 处理。
4. 实现、运行相关检查及真实组合验证。实际可用后将模块和代码资产改为 active，更新当前说明。

## 每次修改

先 context 读取模块及规则，再 impact 检查受影响对象。已有接口满足需求则沿用。影响长期选择时写 proposed 决策，记录真实备选；已有授权且范围清楚的常规工作直接推进。

活动记录写目标、范围、完成情况、问题和下一步，按一次有意义的作业更新，不为每条工具调用生成文档。跨模块变更复用同一活动记录，用 affects 指向多个对象。

## 完成与核对

核对实际产物和结果，更新模块主记录及受影响专题，补充或修正关系。新增重要决策时同步处理旧决策的完整或部分替代。

运行 check；修复重复 URI、失效引用、错误关系、缺少主记录章节及放错位置的独立文档。再运行 check --logic 核对规则层登记的业务规则；违反项按报告中的决策点和方案由人选择处理方式，工具不自动修改。运行 index 更新派生索引。若模块已有核对指纹而本次内容改变，先实际核对语义和必要测试，再更新验证记录并执行 checkpoint。最后 check --strict 检查活动模块的核对指纹。

checkpoint 只是核对者留下的记录，不执行测试，也不自动判断文档与代码意思相同。验证记录必须写实际执行的命令、结果、对应对象和限制。复制项目后不继承旧的核对指纹。

## 中断、失败与恢复

保存已经完成的对象、实际产物 URI、错误、未完成项和下一动作。恢复时读取活动记录并检查磁盘与 CLI，不把上一次口头“完成”当证据。重复执行前确认哪些步骤可以安全重跑；无把握的写入先保留已有产物。

业务范围、用户取舍或来源无法判断时，用业务语言说明选项和后果；不要求用户补编程知识。源资料错误、接口冲突和未运行检查分别报告。

## 旧项目渐进接入

先只读盘点，建立现行入口、模块主记录和位置映射，标记历史来源；不按目录名直接删除或合并。文档迁入独立文档根需要执行既有授权范围内的迁移和引用核对。本包不会自动搬动原项目或修改外部项目。
