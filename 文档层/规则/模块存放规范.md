# 模块存放规范

## 代码层分区

代码层按角色分区，模块与入口、外部代码分开：

```text
代码层/
├── packages/   可复用模块，固定放在 packages/<分组>/<模块>/
├── apps/       可运行入口（CLI、Web、桌面）
├── vendor/     外部钉版代码，原样存放
├── scripts/    按需质检与生成器
└── tests/      跨模块组合验证
```

模块恰好比其分组低一层。分组是纯容器，只做命名空间，不直接放源码或配置；小项目可用单一默认分组，需要时再增设。

## 分区职责

- apps/：只放可运行入口，不放可复用逻辑。
- packages/：可复用组件，主要开发面；一个模块一个目录，实现与测试都在其目录内。
- vendor/：拉取的开源代码原样存放，不与自有模块混放；引用时记来源与版本。
- scripts/：质检与生成器，由 AI coding 按模块需要生成，并与对应模块或步骤绑定。
- tests/：跨模块组合验证；模块自身的单元检查留在模块目录内。

## 内容与展示分离

文档全部在文档层，代码目录不放 README 或规则，代码内只保留必要的局部注释。站点或展示资产单独存放，只放配置与展示资源，内容仍留在文档层。

## 与主记录和索引的对应

代码实体在治理层登记为 code 资产，用 implements 指向所属模块；模块的职责与输入输出在文档层的模块主记录。移动文件只更新绑定或索引，模块与代码的身份 URI 不变。
