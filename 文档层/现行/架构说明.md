# 当前项目结构

文档根、代码根与治理数据位置通过 project.json 绑定，三者默认在包内平级，也可以分别迁移。文档根和代码根禁止嵌套。

文档层的全局入口是 doc://demo/agent-entry，项目入口是 project://demo。模块主记录是理解模块的第一站；现行专题说明细节，演进记录保留理由与作业经过。

代码实体包括已实现的治理工具 module://demo/docgov，以及计划中的业务模块 module://demo/example。源码、测试和机器定义在代码层；没有 README 或 AGENTS.md。

治理层保存 ontology.json、assets.json 和项目绑定；索引与核对指纹写入独立 state 目录。CLI 每次查询直接读取当前来源，index 是可删除后重建的派生输出。源文件与检查结果仍决定实际状态，索引不成为第二套人工事实。

模块之间用 depends_on 明确依赖，当前两个模块没有业务调用依赖。通用 ontology 不包含书籍、产品或其他领域对象。
