# MatterLedger 事项台账

给一个会持续多轮的项目，建一本能接得上的上下文台账：事情到哪一步、为什么这样定、哪些方案被否、改这里会影响谁。

## 什么时候用

命中两条以上再启动：

- 项目会持续多轮，不是一次性任务。
- 上下文散在聊天、文档、代码和人的记忆里。
- 需要跨会话接续，换个 Agent 也要能接上。
- 有重要取舍需要留痕，以后不想再讨论一遍。
- 用户明确说「帮我管这个项目」「记一下进展」「AI 又忘了」「文档太乱」。

不启动：

- 一次性问答、单文件改写、纯查询。
- 用户只是要一个模板，不需要建目录。
- 用户没有授权写文件。

## 启动前先问三件事

一次问完，不要逐条追问：

1. 项目叫什么名字？
2. 建在哪里？默认当前工作目录，必须确认。
3. 是新项目，还是已有项目？

## 新项目：创建

在 Skill 根目录执行：

```
python3 scripts/init_ledger.py --target "<目标目录>" --name "<项目名>" --id "<project-id>"
```

脚本会复制 `assets/starter/`，替换占位符，生成：

```
<项目名>/
  项目说明.md
  事项台账.md
  决策记录/
  模块/
  参考/
```

如果目标目录已存在且非空，脚本会停止并报错；不要覆盖，先问用户。

如果运行环境没有 Python，直接复制 `assets/starter/` 到目标目录，手动替换 `{{PROJECT_ID}}`、`{{PROJECT_NAME}}`、`{{DATE}}`。

创建后，在 `事项台账.md` 写下第一条：

- 事项：用户这次要推进的具体事。
- 当前阶段：候选 / 进行中 / 待验证 / 已交付 / 暂缓。
- 下一步：谁在什么时候做什么。
- 关联：相关决策或作业记录。

## 已有项目：只读接入

1. 先只读盘点：入口文档、模块、现有决策记录、当前状态。
2. 建议新建一个 `事项台账/` 子目录，不搬动、不覆盖原文件。
3. 先补三样：项目说明、事项台账、第一个模块主记录。
4. 得到用户确认后再写入。

## 每次工作循环

- 开工：先读 `事项台账.md`，再读目标模块的 `AGENTS.md`。
- 遇到取舍：写一份决策记录，必须包含「真实备选 + 未采用理由」，不要只写结论。
- 收工：更新事项阶段、下一步和最后更新日期；必要时补一份作业记录。
- 每周：扫一遍台账，把停滞的事项标出来，不删除放弃项，写明原因。

## 三份核心文档

事项台账：一行一件事。列：事项、当前阶段、下一步、关联决策/作业、最后更新。阶段固定五档，不临时造词。

决策记录：问题、真实备选、提案与验收、替代情况。状态三态：proposed / implemented / rejected。多数项目只记最后定了什么，这份补的是「为什么」和「哪些被否」。

模块主记录：职责、输入与输出、开发与验证、关联资料。一个模块一份，不另写重复 README。

## 可选：完整治理包

需要文档层、代码层、治理层和 CLI 时，取完整包：

https://github.com/dchao0115/matter-ledger

CLI 提供 `context`（取上下文）、`impact`（查影响面）、`check`（查结构与规则）。没有 Python 也能用，只是查询要手动。

## 边界

- 不覆盖非空目录，不写到目标目录之外。
- 不把密钥、客户信息、内部项目名写进公开示例。
- 不调用模型 API，不替用户做业务判断。
- 这个 Skill 在用户自己的电脑或 Agent 虚拟机里创建目录，不在 Skill 安装目录里写业务数据。
- 先确认再写入；用户没授权就不建。

## 验收

- 目标目录存在，且有 `事项台账.md`、`决策记录/`、`模块/`。
- 台账第一条有阶段和下一步。
- 用户能回答：「现在有几件事，各自到哪一步？」
